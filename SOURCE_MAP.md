# paperclip-company-standards — Source Map

Recommended read order for any agent or developer picking up this repo.

**Grok Bot seat path:** README → this file after CONTEXT → operator stack → new-company checklist. That path bootstraps a 3-slot Cursor game company. Do not follow the 13-central or five-slot sections as spawn instructions.

## 1. Orient (start here)

1. `README.md` — what this repo is, who owns it, Grok primary profile, branch model
1a. `AGENTS.md` — **the agent guide, and the first file most harnesses load automatically.** What this repo is for, what must never happen in it, the three ways changes go wrong here, and the pre-completion checklist. Also disambiguates this repo's own `AGENTS.md` from the company-scoped ones generated by `standards/sync-bootstrap.sh`. `CLAUDE.md` points at it rather than repeating it
2. `CONTEXT.md` — domain glossary; decode all jargon before reading docs
3. `SOURCE_MAP.md` — this file; orient read order

## 2. Issues and known gaps (read early)

4. `docs/known-issues.md` — open KIs; check before making decisions that touch open questions. KI-PS-1: Grok seats are 3-slot; five-slot is the Knowledge-central portfolio only

## 3. Grok primary path (foundation)

5. `docs/operator-stack.md` — MCP primary, CLI fallback, browser never default, docs.paperclip.ing
6. `docs/company-architecture.md` — 3-slot Cursor game company first; 13-central / five-slot marked legacy
7. `docs/flows/new-company-checklist.md` — MCP-first create/hire; CLI for wake/approvals/checkout/budgets
8. `docs/governance/model-topology.md` — Cursor lock supersedes Claude/Codex for Grok-created companies
9. `config/models.json` — canonical model assignments (primary + `legacy_five_slot`)
10. `config/roles.json` — 3 required slots; optional specialists; API role mapping

## 4. Agent bootstrap configs

11. `docs/ceo-bootstrap.md` — CEO behavioral contract; model/adapter from `config/models.json`
12. `docs/worker-bootstrap.md` — Worker behavioral contract; model/adapter from `config/models.json`

## 5. Optional specialists (not Grok spawn)

14. `docs/specialists/researcher.md` — same

## 6. Operational flows

15. `docs/flows/weekly-knowledge-aggregation.md` — skip on Grok 3-slot companies until a Keeper exists

## 7. Governance

17. `docs/governance/paperclip-version-policy.md` — semver policy; when to bump major/minor/patch

## 8. Role packs

18. `roles/_shared/CONTEXT.md` — canonical vocabulary for all roles; read before any role doc

## 10. Standards

29. `standards/reviewer-pattern.md` — end-to-end gate flow: worker done → reviewer → verdict → Done to deputy
30. `standards/sync-bootstrap.sh` — idempotent merge to company-scoped AGENTS.md; never touches host CLAUDE.md
31. `standards/approval-wake-protocol.md` — PAPERCLIP_APPROVAL_ID handling; checkout-before-work; 409 rule
32. `standards/cc-paperclip-communication-protocol.md` — board-deputy-to-CEO-only; Grok Bot seat is the deputy
33. `standards/worker-skills-catalog.md` — cross-role index of all skills, sources, target roles
34. `standards/parallel-work-isolation.md` — one worktree per concurrent worker; shared runtime state is CEO-owned; dependency waves with a concurrency cap. Sequential is the default

## 11. Machine-readable config (canonical values)

35. `config/skills-manifest.json` — all skills, source repos, target roles, versions
36. `config/required-tools.json` — Claude-host required tools (not a Grok spawn gate)
37. `config/central-companies.json` — 13-central registry; `grok_bot_seats_bootstrap_this_layer` is false
38. `scripts/validate-grok-profile.sh` — machine check that the Grok primary profile is what the JSON says
